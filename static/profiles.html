Profils de minage

Profils (§4.5)

Un profil décrit comment mine un coin : binaire (URL + SHA256 obligatoire), gabarit de ligne de commande, port d'API, mode d'exécution. Variables autorisées : {wallet} {pool} {worker} {gpus} {threads} {api_port}. Le gabarit est découpé avec shlex puis substitué ; la commande reste un tableau d'arguments, jamais une chaîne pour un shell.

Binaires déjà installés

Adopter : Fossor lit le SHA256 du binaire présent sur la machine et le compare à celui du profil — identique, le profil est marqué installé, sans réinstallation. Importer : le binaire est récupéré par SFTP dans Fossor (SHA256 vérifié), pour l'installer ailleurs.

Nouveau profil

Motif imposé : ^[A-Za-z0-9:._-]{8,128}$ — espaces, ;, $ et backticks refusés.
Motif : ^(solo|stratum(\+tcp|\+ssl)?://[A-Za-z0-9.-]+:\d{2,5})$
Vérifié par sha256sum sur la machine cible avant extraction ; différent ⇒ refus et archive supprimée.
Installé dans /opt/fossor/miners/<logiciel>/<version>/
Avec un port d'API, la campagne vm interroge le mineur dans la VM (sinon : dernière ligne de hashrate de son journal).
Adresse seule : le contrôle vérifie qu'aucun fichier wallet n'existe dans le dossier data de la VM et l'écrit au journal.
Binaire Fossor : archive déposée ici, SHA256 calculé et affiché, poussée dans la VM par le même canal que l'image et vérifiée des deux côtés. Jamais exécuté sans somme vérifiée.
