📖 Comment ça marche

La veille propose, Fossor valide, Fred approuve — ou le lancement automatique s'applique.
Hermes : veille→ Fossor : règles et validation→ Fred : approbation→ Lancement (manuel ou auto)

a. Principe

Par défaut, toutes les machines minent le token de référence (Pearl). La veille cherche des coins tout juste lancés, minables par nos machines, pour les miner tôt pendant que le réseau est petit. Ce n'est pas un calcul de rentabilité immédiate.

Dans Fossor, le partage est net : Hermes propose une analyse et, si un candidat est retenu, une proposition de campagne ; Fossor valide cette proposition contre ses règles (fraîcheur, rôle des devices, capacité, durée, part réseau) ; Fred approuve, sauf si la règle de lancement automatique est active pour le type de device concerné.

c. Le cycle

Le tick de veille est déclenché par Fossor (bouton ou cadence de la règle watch_cadence, 6 h par défaut). Hermes lit le contexte Fossor, scanne ses sources (ANN Altcoins de Bitcointalk, nouveaux coins de miningpoolstats, versions de SRBMiner-Multi / lolMiner / BzMiner), filtre, évalue, puis dépose une analyse — et une proposition seulement si un candidat est retenu et minable.

Aucune commande SSH n'est exécutée par le tick : Fossor ne lance ni n'arrête un mineur à cette étape.

d. Filtre et évaluation

Critères de sélection
  • Coin de moins de 72 h (idéal < 48 h)
  • Minable (GPU NVIDIA ou CPU)
  • Miner connu ou officiel vérifiable
Éliminés d'office
  • Algorithmes ASIC dès le lancement (SHA-256, Scrypt…)
  • Tokens ERC/BNB/Solana
  • Browser-mining
  • « IA » sans miner
Pas éliminés d'office
  • CPU-only
  • Pool absent, unique ou solo au lancement
  • Coin de 3 à 7 jours avec signaux frais (→ surveillance)
  • Coin déjà listé (→ rentabilité estimée en €/j)

Utilité, équipe (compte Bitcointalk, GitHub), fraîcheur, signaux on-chain. Red flags : premine cachée, dev totalement anonyme, algo maison + binaire invérifiable, demande de seed, faille consensus ouverte.

e. Verdicts

Trois verdicts : retenu surveillance rejeté — mêmes couleurs que les puces de filtre de l'onglet Analyse des tokens. Un verdict supplémentaire présent dans les données obtient sa propre puce.

f. Décision de bascule

S'y ajoute une condition : (a) moins de 72 h, (b) minable avec un miner fiable, (c) aucun red flag critique, (d) au moins un signal positif. En cas de doute, pas de bascule. Fossor refuse en plus une proposition hors fenêtre de fraîcheur, sur un device non autorisé, occupé, ou dont la durée dépasse la règle de durée.

  • GPU → la 4080 passe dans la VM de spec (Pearl coupé sur la 4080 seulement)
  • CPU → VM specbox jetable (Pearl intact)
  • Toujours un wallet neuf dédié, créé dans la VM

g. Pendant une campagne

  • Durée de base 96 h
  • « La sauce prend » → prolongation +96 h
  • « Ça sent le sapin » → arrêt anticipé et retour Pearl
  • Neutre → jusqu'à l'échéance
  • Campagnes CPU : sans limite, arrêt seulement si chaîne morte ou décision de Fred

Le tableau de bord affiche l'échéance, les prolongations, le hashrate, le solde du wallet et la dernière note. Pour une campagne solo, le solde vient du nœud (commande getbalance en liste blanche, lecture seule) ; sinon c'est la dernière valeur importée, avec sa date.

h. Messages

Messages à Fred : uniquement bascule, prolongation, rapport de fin. Sinon silence. Fossor journalise chaque décision dans le Log et dans les événements de campagne.

j. Lancement automatique

Pilotage réel par machine. Une machine armée avec le mot PILOTER agit en réel, même si la simulation globale est active. Une machine non armée reste toujours simulée, quel que soit le global : le global ON est la valeur par défaut des machines non armées, et le passer à OFF n'arme aucune machine. Les ASIC ne sont jamais pilotés, armés ou non.

La règle auto_launch peut être activée séparément pour le GPU et pour le CPU. Quand elle est active, une proposition validée par Fossor est lancée sans approbation, uniquement sur des devices autorisés et des machines dont la simulation est désactivée ; sinon, elle est simulée. Elle est livrée désactivée : Fred confirme avant de l'activer.
